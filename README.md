# Ifeel

Трекер менструального цикла, который помогает лучше понимать связь между фазой цикла и самочувствием.

## Зачем

Я часто сталкиваюсь со сменой самочувствия из-за цикла, даже не понимая этого. Общая информация есть: в середине цикла овуляция и приподнятое настроение, в конце лютеиновая фаза и повышенная раздражительность. Проблема в том, что это усреднённая картина, а каждая проходит через фазы по-своему.

Ifeel не рассказывает, как должно быть. Он собирает твои собственные оценки за несколько циклов и показывает твои личные закономерности: например, что в лютеиновую фазу ты в 70% записанных дней отмечала низкую энергию.

## Приватность

Приложение работает с чувствительными данными о здоровье, поэтому приватность заложена в архитектуру с первого дня, а не добавляется в конце.

**Уже реализовано**

- Собирается только то, что нужно самому приложению. Пользователь не указывает почту, телефон или что-либо ещё, не относящееся к циклу и самочувствию.
- Никакой сквозной аналитики по пользователям. Приложение считает выводы только для тебя и только по твоим данным.
- Не подключены сторонние сервисы: ни аналитики, ни рекламных SDK, ни внешних API. Данные никуда не уходят за пределы приложения.
- Секреты не попадают в репозиторий: пароль от базы хранится в переменной окружения `DB_PASSWORD`, в `application.properties` только ссылка на неё.

**В планах**

- Хранение паролей только в виде хэша.
- Экспорт всех своих данных одним файлом.
- Полное удаление аккаунта вместе со всеми данными.
- HTTPS при деплое, чтобы данные не передавались по сети открытым текстом.
- Шифрование чувствительных полей ключом, выведенным из пароля пользователя.

## Стек

- Java 21 (Amazon Corretto)
- Spring Boot 4.1.0 (Web MVC, Spring Data JPA, Validation)
- PostgreSQL 17 (в Docker)
- Maven, Lombok
- Frontend: React + TypeScript (планируется)

## Статус

Проект в активной разработке.

Работает:
- модель данных: циклы, дневные логи, справочник симптомов с оценкой выраженности
- запись и чтение данных о менструациях через REST API

В работе:
- эндпоинт дневного лога
- вычисление фазы цикла по датам начала месячных
- агрегация самочувствия по фазам за несколько циклов
- аккаунты и изоляция данных между пользователями

## Архитектурные решения

**Симптомы хранятся в отдельной таблице, а не списком тегов.** Один из главных принципов приложения — индивидуальность, а такое хранение позволяет добавлять пользовательские симптомы, которые не были учтены дизайном приложения.

**Таблица `symptom_rating` нужна не только для связи многие-ко-многим между днями и симптомами, но и для хранения выраженности симптома.** Просто поставить галочку «головная боль» — не то же самое, что оценить её от 1 до 5. Ранжированная оценка точнее отражает состояние и даёт больше для последующей статистики.

**Сервер, а не local-first.** Хранение только на устройстве было бы приватнее по умолчанию, но тогда данные не синхронизируются между телефоном и ноутбуком, а вся логика расчёта фаз и агрегации теряет место, где ей выполняться. Поэтому сервер есть, но приватность обеспечивается его дизайном: минимум собираемых данных, отсутствие сторонних сервисов и контроль пользователя над своими данными.

**Настроение как enum, а не число от 1 до 5.** Шкала «плохое/хорошее» слишком широкая. Плохое настроение бывает разным: грусть, раздражительность, тревога, апатия. Мне нужно знать максимально конкретно, чего ожидать от следующей недели, чтобы вывод звучал не как «начинается лютеиновая фаза, настроение будет плохим», а как «в лютеиновую фазу ты обычно отмечаешь тревогу».
